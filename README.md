# 🍚 오늘 뭐 먹지?

혼밥러를 위한 메뉴 룰렛. **버튼 한 번**으로 오늘 먹을 메뉴를 정해 주는 단일 페이지 웹앱입니다.

> "오늘 뭐 먹지?"를 고민하는 데 드는 결정 피로를 없애는 게 목표입니다. 메뉴를 직접 고르지 말고, 룰렛에 맡기세요.

---

## 주요 기능

- **버튼 한 번 추천** — `🎲 메뉴 추천받기`를 누르면 후보 중 하나를 랜덤으로 골라 줍니다.
- **필터** — 원하는 조건으로 후보를 좁힐 수 있습니다.
  - **카테고리**: 한식 / 일식 / 중식 / 양식 / 분식 / 패스트푸드 (다중 선택)
  - **조리방식**: 직접 요리 / 배달 / 외식 (다중 선택)
  - **혼밥친화**: 혼자 먹기 좋은 메뉴만 보기 (기본 ON)
  - 필터를 바꾸면 `후보 N개` 카운트가 실시간으로 갱신됩니다.
- **룰렛 연출** — 추천 시 메뉴가 빠르게 바뀌다 약 0.7초 후 멈춥니다. (모션 최소화 설정 시 빠른 페이드로 대체)
- **다시 돌리기** — 결과가 나오면 버튼이 `🔄 다시 돌리기`로 바뀝니다. 후보가 2개 이상이면 **직전 결과는 빼고** 다시 뽑아 줍니다.
- **후보 0개 / 1개 처리**
  - **0개**: 추천 버튼이 비활성화되고, `필터 초기화` 버튼이 있는 안내 배너가 뜹니다.
  - **1개**: "후보가 1개뿐이에요." 안내가 표시되고 그 메뉴가 바로 선택됩니다.
- **근처 식당 찾기** — 메뉴가 추천되면 `‘OO’ 파는 근처 식당` 섹션이 열립니다. 동네를 입력하고 `🔍 찾기`를 누르면 그 메뉴를 파는 근처 식당 목록(이름·카테고리·거리·주소, 카카오맵 링크)을 보여 줍니다. 입력한 동네는 브라우저에 저장돼 다음에 자동으로 채워집니다.

---

## 근처 식당 데이터 (카카오맵 API)

근처 식당 기능은 **카카오맵 JavaScript SDK(키워드 장소 검색)** 를 사용합니다. 도메인 제한 JS 키라 백엔드 없는 정적 앱에서도 안전하게 동작합니다.

**키 없이도 동작합니다.** 키를 넣지 않으면 화면 확인용 **샘플(더미) 데이터**가 표시되고, 키를 넣는 즉시 같은 화면이 실제 데이터로 전환됩니다.

### 카카오 JS 키 발급 (약 3분, 한 번만)

1. [developers.kakao.com](https://developers.kakao.com) 에 카카오 계정으로 로그인
2. **내 애플리케이션 → 애플리케이션 추가하기** (이름은 자유)
3. **앱 키** 탭의 **JavaScript 키**를 복사
4. **플랫폼 → Web 플랫폼 등록**에 앱을 띄울 도메인 추가 (로컬은 `http://localhost:8000`)

발급한 키를 `js/config.js`에 붙여넣으면 끝입니다.

```js
// js/config.js
export const KAKAO_JS_KEY = "여기에_발급받은_JavaScript_키";
```

> 동네 이름이 주소로 인식되면 그 좌표 주변을 **거리순**으로 검색하고, 아니면 `동네 + 메뉴` 키워드로 검색합니다. `SEARCH_RADIUS`(반경), `MAX_RESULTS`(개수)도 `config.js`에서 조정할 수 있습니다.

## 실행 방법

이 앱은 **ES module(`import`/`export`)** 을 사용합니다. 따라서 `index.html`을 `file://`로 직접 열면 모듈 로딩이 막혀 **동작하지 않습니다.** 반드시 로컬 정적 서버로 실행하세요.

```bash
# 프로젝트 루트에서
python3 -m http.server 8000
```

그 후 브라우저에서 접속:

```
http://localhost:8000
```

별도의 설치나 빌드 과정은 없습니다.

## 파일 구조

```
mbdev/
├── index.html        # 마크업 + 정적 요소
├── css/
│   └── style.css     # 스타일 (디자인 토큰, 카드/칩/스위치/룰렛 애니메이션)
└── js/
    ├── data.js        # 메뉴 데이터 + 상수(카테고리/조리방식)
    ├── recommend.js   # 순수 로직(필터링, 랜덤 선택)
    ├── state.js       # 앱 전역 상태 + 후보 재계산
    ├── config.js      # 카카오 JS 키 등 설정
    ├── restaurants.js # 근처 식당 검색(카카오 API / 더미 폴백)
    └── main.js        # UI 조립(DOM 렌더, 이벤트, 룰렛 연출)
```

| 파일 | 역할 |
| --- | --- |
| `js/data.js` | `MENUS` 배열과 `CATEGORIES`, `TYPES` 상수를 정의. 데이터의 단일 출처. |
| `js/recommend.js` | 외부 상태에 의존하지 않는 **순수 함수** — `filterMenus()`(조건 필터링), `pickRandom()`(직전 결과 회피 랜덤 선택). |
| `js/state.js` | `state` 객체(필터/후보/현재 결과 등)와 `recomputeCandidates()`, `resetFilters()`. |
| `js/config.js` | `KAKAO_JS_KEY`, `SEARCH_RADIUS`, `MAX_RESULTS` 등 설정값. |
| `js/restaurants.js` | 동네+메뉴로 근처 식당을 검색. 키가 있으면 카카오 SDK, 없으면 더미 데이터. `searchNearby()`, `isApiEnabled()`. |
| `js/main.js` | DOM 참조·칩 생성·렌더·이벤트 바인딩·룰렛 연출을 모아 화면을 구성하는 진입점. |

## 메뉴 데이터 추가/수정

메뉴는 모두 `js/data.js`의 `MENUS` 배열에 들어 있습니다. 객체 하나를 추가/수정하면 바로 후보에 반영됩니다. (현재 37개)

### 스키마

```js
{
  id: "kimchi-stew",      // 고유 식별자 (중복 금지, kebab-case 권장)
  name: "김치찌개",        // 화면에 표시될 이름
  emoji: "🍲",            // 결과 카드에 크게 보여줄 이모지
  category: "korean",     // 카테고리 (유효값 아래 참고)
  type: "cook",           // 조리방식 (유효값 아래 참고)
  soloFriendly: true,     // 혼밥친화 여부 (true/false)
  comment: "냉장고 속 김치면 완성, 1인분도 든든." // 결과 카드 하단 한 줄 코멘트
}
```

### 유효값

`category` (6종):

| 값 | 표시 |
| --- | --- |
| `korean` | 한식 |
| `japanese` | 일식 |
| `chinese` | 중식 |
| `western` | 양식 |
| `snack` | 분식 |
| `fastfood` | 패스트푸드 |

`type` (3종):

| 값 | 표시 |
| --- | --- |
| `cook` | 직접 요리 |
| `delivery` | 배달 |
| `dineout` | 외식 |

> `category`·`type`에 위 목록에 없는 값을 넣으면 필터 칩과 매칭되지 않아 후보에 나타나지 않습니다.
> `soloFriendly: false`인 메뉴는 혼밥친화 스위치가 켜져 있을 때(기본값) 제외됩니다.

### 예시: 새 메뉴 추가

```js
// js/data.js 의 MENUS 배열에 추가
{ id: "naengmyeon", name: "냉면", emoji: "🍜", category: "korean", type: "dineout", soloFriendly: true, comment: "더운 날엔 시원하게 한 그릇." },
```

새로운 카테고리/조리방식을 추가하려면 같은 파일의 `CATEGORIES` 또는 `TYPES` 배열에 `{ id, label }` 항목을 더하세요. 필터 칩이 자동으로 생성됩니다.

## 기술 스택

- **순수 바닐라 JavaScript (ES modules)** — 프레임워크·라이브러리 없음
- **HTML + CSS** — CSS 커스텀 프로퍼티(디자인 토큰) 기반
- **빌드 도구·의존성 없음** — 정적 파일만으로 실행
- 접근성 고려: `aria-*` 속성, `:focus-visible`, `prefers-reduced-motion` 대응
